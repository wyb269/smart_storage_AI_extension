# 种芯粮安智控管理平台研发项目 AI 算法模块开发

本仓库收录公司项目 `feature/ys` 分支的前后端源码，是一份**脱敏快照**。本次开发包含两组能力：**八类 AI 视觉监测场景**，以及**熏蒸、粮情、虫害、通风四类作业辅助计算**。前者建设监测与事件处理链路，后者根据人工输入的仓储参数计算风险或方案。仓库不包含可直接用于生产识别的模型权重。

## 功能全貌

两组能力的输入、计算和输出不同：

| 能力 | 输入 | 处理 | 输出 |
| --- | --- | --- | --- |
| AI 视觉监测 | 点位、摄像头、设备状态、事件与媒体引用 | 查询状态和事件；提交并追踪识别任务 | 状态卡片、历史事件、算法任务、处理记录 |
| 作业辅助计算 | 仓房、粮食、虫情、天气、设备及历史参数 | 参数完整性检查、规则判断和公式计算 | 风险分级、预警项、可行性校核、作业建议或方案 |

视觉场景的业务链为**监测对象 → 算法任务 → 事件 → 查看与追溯**；作业辅助的业务链为**人工填写参数 → 缺项追问 → 后端计算 → 展示结论与依据**。两者共用管理平台，但不能把辅助计算页面理解成已经接入大语言模型或真实视觉模型。

## 一、八类 AI 视觉场景

| 场景 | 监测对象与输入 | 页面及事件输出 |
| --- | --- |
| 仓门异动监测 | 仓门、绑定摄像头、设备与告警状态 | 仓门状态和异动事件；详情包含位置、时间、算法任务与处理记录。 |
| 视频遮挡检测 | 摄像头、位置、画面遮挡状态 | 摄像头状态和遮挡事件，支持按条件查询历史。 |
| 人员行为监测 | 作业区域、摄像头、行为类型 | 人员聚集、未戴安全帽、倒地、区域闯入等事件。 |
| 地面积水监测 | 通廊等监测点位、摄像头、积水类型 | 干燥或积水状态，以及积水、渗漏等事件。 |
| 皮带机下站人监测 | 皮带机点位、摄像头、人员行为 | 危险区域出现人员等事件及设备状态。 |
| 周界入侵识别 | 东西南北防区、摄像头、布防状态 | 入侵告警、未布防与离线状态，以及防区事件。 |
| 粮面虫害智能识别 | 仓房、采样位置、摄像头、虫情数据 | 仓房虫情状态、虫种或密度相关检测事件。 |
| 车辆智能识别 | 今日识别记录、摄像头与出入口 | 车牌、车型、入库或出库方向、识别地点及历史事件。 |

每类场景都有**监测页**和**历史页**，共 16 个页面。监测页提供监测对象或今日车辆列表、监控区域和最近事件；历史页提供条件查询、分页、详情与导出。前七类场景的状态卡片使用图标和颜色区分正常、异常、离线等状态；设备是否在线以接口返回的设备状态为准。

### 视觉场景的实现方式

1. **前端页面**：`manage/src/pages/aiVision/` 按场景拆分组件，复用轮询、状态计算、任务展示和处理记录组件。监测页定时请求状态及最近事件；历史页按条件分页查询，详情弹窗展示事件、任务和处理过程。
2. **状态计算**：前端根据接口返回的 `deviceStatus` 和 `alarmStatus` 计算展示状态。未知或缺数据为“未知”，明确离线为“离线”，在线且存在有效告警为“异常”，否则为“正常”。颜色和图标由这一结果驱动；心跳时间只作诊断，不能替代接口设备状态。
3. **后端接口**：`smart-storage-admin` 为八个场景分别提供监测对象或今日车辆、视频信息、最近事件、历史查询、详情、导出、查看事件和算法任务接口。Controller 接收请求，Service 处理业务，Mapper 访问场景数据。AI 视觉数据源与原业务主库分开；未启用专用数据源时可回退到内存实现联调。
4. **事件处理**：打开详情时调用 `markEventViewed/{eventId}`。未处理事件转为已处理，并追加处理记录；重复查看按幂等方式处理。前端保留“查看”入口，不要求用户再点单独的“处理”按钮。
5. **算法任务**：点击“重新识别”调用 `rerunAlgorithm/{eventId}`，接口先返回任务号，页面再查询 `algorithmTask/{taskId}`。任务经历排队、运行、成功、失败或超时；前端以约 800 毫秒间隔、最多 20 次轮询，结束后刷新详情与列表。详情显示任务号、模型与算法版本、置信度、耗时和结论。后端保存任务记录，成功时回写事件的算法字段；失败或超时保留任务状态，不修改人工处理状态。
6. **数据与权限**：后端按场景组织监测点位、事件、证据、处理记录和算法任务等数据；`service/docs/` 提供建表、回滚及示例数据脚本。接口同时应用登录身份、数据范围和功能权限检查。视频地址和事件媒体通过受控接口处理，不由前端拼接永久摄像头地址。

## 二、四类作业辅助计算

这四个页面由另一位开发者在同一 `feature/ys` 分支实现。页面采用左侧参数表单、右侧结果区的形式。熏蒸、粮情和虫害页面可从仓房列表选择仓房；四个页面的作业参数都由人员填写。前端调用 `/ai` 下的四个接口；后端先检查关键参数，缺少时返回待补字段及追问文案，齐全时执行确定性的规则与公式，返回结构化结果。前端用 `useStreamReveal.ts` 逐段展示已收到的完整结果。这个动画不代表服务端逐字生成，也不代表已接入大语言模型。

### 1. 熏蒸作业辅助

- **输入**：仓型与空间/粮堆体积、气密性或压力半衰期、粮种与水分、最低粮温、虫种与虫口密度、抗药性、天气、施药方式，以及可选的气体浓度等参数。页面可选择仓房；作业参数主要由人员填写。
- **计算过程**：先对气密、温度、水分、天气、杂质等条件做作业前校核；再根据虫种及抗药性分组、内置规则和允许的人工覆盖值确定建议密闭时间与目标浓度。程序以“目标浓度 × 密闭小时数”计算浓度时间积（CT），结合粮堆与仓房空间体积估算用药量、药片数及施药点分配，并生成阶段安排与浓度检测节点。
- **输出**：作业可行性、风险提示、药剂与剂量估算、时间安排、检测计划、操作步骤及安全警示。对应接口为 `POST /ai/fumigation/generatePlan`。
- **业务边界**：这些数值是源码内置规则计算出的辅助建议，不能替代持证人员对现场气密、浓度、人员防护和现行作业规程的核验；页面没有自动投药或设备控制能力。

### 2. 粮情分析

- **输入**：仓房与粮种、粮堆测温点、平均/最高粮温及升温速率、虫口密度、粮食水分、仓内外环境和历史异常等。页面表单将数据组织成粮温、虫害、水分、环境等分组传给后端。
- **计算过程**：按粮温、虫害、水分、环境四个维度分别计算风险分，维度上限依次为 30、30、25、15 分；若有历史复发，按代码规则提高相关风险分并受上限约束。总分为四项之和且不超过 100；`≥70` 为高风险，`≥40` 且 `<70` 为中风险，其余为低风险。粮温趋势采用线性外推：`预计最高粮温 = 当前最高粮温 + 日升温速率 × 预测天数`，不是机器学习预测。
- **输出**：总风险分和等级、分维度预警、摘要、处理优先级与处置方案。对应接口为 `POST /ai/grainAnalysis/analyze`。分数用于排序和提示，不应直接解释为“事故发生概率”。

### 3. 虫害分析

- **输入**：虫种及各采样点密度、主要害虫密度、粮温与水分、仓房密闭条件、既往防治效果和环境条件。使用最高采样点密度（缺失时用总密度）及主要害虫密度判级，并对检疫性害虫单独提高风险。
- **计算过程**：代码中的基础分级阈值为总密度 `5`、`30` 头/kg，主要害虫密度 `2`、`10` 头/kg；再综合环境、气密性、抗药性、历史虫情和卫生条件生成风险项与分数。方案 A 调用熏蒸计算逻辑生成熏蒸与清洁组合；方案 B 借用通风规则判断低温通风的可行性；方案 C 为物理防治。程序比较方案适用性并给出复查建议。
- **输出**：虫情等级、风险解释、方案 A/B/C 的可行性与推荐理由、后续采样复查要求。对应接口为 `POST /ai/pestAnalysis/analyze`。页面中的预期防效、成本等属于预设估计，不能当作现场实测结果。

### 4. 通风作业辅助

- **输入**：降温、降水、调质或平衡防结露目标；粮食质量、体积、容重、粮温、水分和粮堆高度；风机数量、单机风量/功率、风道面积；逐小时天气及作业时段约束。页面提供可编辑的 24 小时**示例天气曲线**，由本地正弦函数生成，不是实时天气接口。
- **计算过程**：先校核单位通风量与设备能力，按 `总风量 = 单位通风量 × 粮堆体积 × 容重` 估算需求，再计算粮层阻力、风机压力、主/支风道风速和间距等。对每个候选小时检查温湿度、露点、降雨、允许时段和连续作业时长等条件，筛选通风窗口；最后估算降温、耗电和停止条件。
- **输出**：风机及风网校核、建议通风时段、效果和能耗估算、操作步骤与停机条件。对应接口为 `POST /ai/ventilation/generatePlan`；结果是作业建议，不会远程启停风机。

### 模块之间如何协同

虫害分析会复用熏蒸辅助的剂量/时长计算和通风辅助的低温通风可行性判断，但四个页面仍是各自独立的请求与结果。共享的“缺项追问”只提示补齐输入；当前接口没有方案保存、审批或实际执行闭环。实际业务可按“采样/巡检数据 → 风险判断 → 人工核对方案 → 线下执行 → 复测”使用，复测结果需要重新录入，系统不能自动证明措施有效。

## 当前边界

- **识别算法**：当前后端使用模拟算法适配器完成任务提交、状态流转和结果落库；真实模型与推理服务尚未接入。页面展示的模型及版本字段不代表已经部署对应的真实模型。
- **视频播放**：已实现播放信息接口和页面容器；能否播放取决于现场摄像头、视频平台及播放地址是否接入。
- **事件图片**：前端内置的八张场景图片用于界面展示，可复用；它们不是对应事件的现场取证图片。
- **设备状态**：页面可定时刷新接口数据，但实际在线、离线和异常状态仍取决于上游设备与服务端数据，不能仅凭页面刷新保证实时采集。
- **作业辅助**：四类计算基于当前源码中的规则、阈值和人工输入；尚未接入大语言模型、实时气象数据或自动设备控制。结果区的逐段文字是前端展示动画，预期防效和能耗等是估算值。熏蒸等高风险作业必须由有资质人员核对现场数据和适用规范后决定。

## 源码位置与构建

| 目录 | 内容 |
| --- | --- |
| `manage/src/pages/aiVision/` | 八类场景的监测页、历史页、详情弹窗和共享组件。 |
| `manage/src/pages/aiAssist/` | 四类作业辅助页面及结果逐段展示逻辑。 |
| `manage/src/api/` | 视觉场景与四类作业辅助的前端接口封装。 |
| `service/smart-storage-admin/` | 视觉场景接口、事件与算法任务；`AiAssistantController` 及四类规则计算服务。 |
| `service/docs/` | 各场景的数据库脚本与说明。 |

前端使用 Vue 3、TypeScript、Vite 和 TDesign；后端使用 Java 21、Spring Boot 和 Maven。前端部署构建脚本为 `npm run build:deploy`，发布资源路径为 `/web/`，接口路径前缀为 `/smart-storage-admin`。实际运行还需要配置数据库、缓存、对象存储和权限等环境参数。
